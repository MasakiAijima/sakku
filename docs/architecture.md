# Sakku — Webからスマートフォンアプリへ
更新：2026-10-11。工程4の採用した基盤と未決定の構成を区別する。

## 体験を支える構成
情景文は本人作成、完成には情景文とhaikuが必須。補助欄は任意。
Web UI → 認証付き記録API → D1という構成を維持する。
shared/contracts.tsとshared/api-client.tsはReact・Workers・DBに依存しない。
lib/validation.tsは純粋な入力検証としてWebと将来のモバイルで再利用できる。
モバイル画面そのものや認証対応を実装したという意味ではない。

| 層 | 現在 | スマートフォンへの拡張 |
|---|---|---|
| 画面 | Vinext／React | React Native／Expoを第一候補（未採用） |
| 共通データ | TypeScriptの契約・入力ルール・通信クライアント | 共有パッケージとして移す。UIは端末ごとに実装 |
| サーバー | Workers／D1 | 記録APIとAI呼出しを共用する設計 |
| 認証 | SitesのChatGPT認証、owner_idはプラットフォーム由来 | モバイル利用可否を確認してから選定。現在の認証を迂回しない |
| 同期 | 明示保存・版・再送キー | オフラインの保存・衝突表示は未決定 |
| 画像 | 保存・生成未実装 | 画像本体はオブジェクトストレージ、メタデータはDBという案 |

Expoの公式資料はTypeScriptと複数アプリでコードを共有するモノレポ構成を説明している。
https://docs.expo.dev/guides/monorepos/
https://docs.expo.dev/guides/typescript/
これは候補選定の根拠であり、既存Web UIや認証が自動で移行できるという保証ではない。

## POP × VISUALY
参照：ユーザーのムードボード「スクリーンショット 2026-10-11 8.58.11.png」。
左上のDO象限：視覚的な積み重ね、軽やかな形、色面。One Yearの体験を参照。
重厚な詩集のような装飾や、長い説明を中心とした見せ方はムードの優先対象にしない。
shared/design-tokens.tsに色・角丸・ビジュアル用途を置き、Webは色を実際に参照する。
現在の紫・杏色・生成りは参照からの暫定解釈。作家の最終配色ではない。
個別画像／日別の小モチーフ／季節表紙の用途を予約するが、役割分担の最終採用は工程2・3B。
寒露の冷たい青と朱色、目玉の採否、節気間の色変化は別途検証する。
見た目と保存データを分け、色やイラストを替えても本人の記録は変更しない。

## 一年を読み返すための期間
APIはfrom（開始日を含む）・to（終了日を含まない）・limit・cursorを受け付ける。
日・候・節気・一年は、暦が確定した後に日付範囲へ解決して取得する。
一年の集計や候の境界を現段階で正式な暦として表示しない。
Issue #6の試作は日付指定と明示期間を使う。暦年の一年表示は1月1日始まりの試作と明記し、候・節気の期間は手入力する。正式な暦への分類はIssue #2の決定を待つ。
記録日をそのまま保持し、候・節気用のIDや季節に合う内容は保存時に要求しない。
暦の地域・根拠・版・時間帯・一年の開始は未決定。
未記録期間は期間に記録がない状態であり、架空の詩や感情を生成しない。
一覧は日付・作成時刻・IDの降順でページ分割する。カーソルは期間に結びつく。
ページ読込中の編集・新規作成は一覧が変わりうるため、全ページの固定スナップショットは保証しない。

## 最新の復元と基盤拡張
前節の候補色は履歴。ユーザー指定の試作原本の構成・配色へ復元した。
Next/Vinextは認証付きシェルを描画し、public/screen.jsが試作と同じ画面を操作する。共通契約・保存ロジックは従来どおり。
写真保存はD1のattachmentsとR2、設定はpreferences。生成ジョブはD1で入力の版・候補・使用量を保持し、再送の重複呼出しを防ぐ。
実AIはサーバーの秘密情報＋モデル設定で有効化する。鍵をクライアントに置かない。
まだ実APIは未接続・モバイル認証未検証・暦未確定。工程4全体を完了とは扱わない。
