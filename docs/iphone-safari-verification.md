# iPhone Safariで最初のWeb版検証を行う

2026-10-14、利用者は最初の実機対象をiPhone SafariのWeb版と指定した。#1の先行方針とし、React Native/Expoの採否、Androidの対応、最低OS、正式認証の決定は別に残す。

## 検証前に揃えるもの

- 実iPhoneのモデル、iOSバージョン、Safari設定を記録する。MacのChrome幅変更・WebKit自動化を実機結果として記録しない。
- PR #27以降の対象コミットを配置したHTTPSの検証URLを用意する。localhostのMac画面と別端末のSafariは同じ環境ではない。LAN内の通常HTTPではService Workerのオフライン検証を完了できない。
- 本体ホームは配置先の認証経路を使う。テストヘッダーや固定開発ユーザーを本番認証に採用しない。
- 個人データを含まない検証用記録で操作する。公開季節素材の確認と、本人記録の保存・復元の確認を分ける。

配置・公開・本番認証変更はこの文書では行っていない。対象URLがまだない場合は、ソースとCIを先にレビューし、配置先を決めてから実機へ進む。

## 操作手順

1. Safariで検証URLを開き、ログインからホームへ進む。現在候・進行数・季節年・全72候を確認する。
2. 過年度・未来年度へ切り替える。C完成・C′初期が同じ位置と大きさで表示されることを確認する。
3. 到来済み候の順次成長と完成後の静止を確認する。候の選択で再成長しないことを確認する。
4. 画像をタップし、一覧でも同じ候を選ぶ。選択枠・候名・読み・期間・現在候を確認する。
5. 縦横回転、Safariのアドレスバー伸縮、ページ拡大で横はみ出し・欠け・タップしづらさを確認する。
6. 設定で日本語とEnglishを切り替え、ホーム・候詳細・入力画面へ戻る。
7. 他アプリへ移動して復帰する。Reduce Motion有効時と無効時に、静止・成長・不要な再生を確認する。
8. 「季節の表示をオフラインで利用できます」の表示後、機内モードで再読込する。公開季節専用画面の72候・年選択・日英・一覧が使えることを確認する。認証済みホームや個人記録をオフライン保存したと誤認しない。
9. オンラインへ戻し、本人の設定・記録を再取得する。#5の本番保存試験は本番環境と復元手順が決まってから別途実施する。
10. VoiceOverで候名・現在候・選択状態を読み上げ、図と一覧から選択する。ジェスチャー順序とフォーカス移動、読み上げが重ならないかを記録する。

## 性能の記録

冷起動と素材保存後の再読込、成長中と静止中を分ける。端末・OS・ネットワーク・低電力モード・計測方法・対象コミットを結果と一緒に残す。ロード時間、ピークメモリ、フレーム低下の結果には実測値を用いる。ファイルサイズやMac上のCPU抑制を代用しない。

Safariの開発メニュー等を使えない場合は、その項目を未計測と記録する。体感と数値を混ぜない。
