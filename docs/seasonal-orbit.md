# Seasonal Orbit — 状態と固定アンカー

`shared/seasonal-orbit.ts`は季節年の72候を計算し、`app/seasonal-orbit.tsx`がホーム画面に表示する。`lib/orbit-calendar.ts`は`data/calendar/current.json`が指す採用版をビルド時に収集した版から選ぶ。候名・読み・実日付は採用データに由来し、JSTの候入りで進行する。候固有の完成イラストは未制作のため、現在は仮アートであることを画面に明示している。

## 入力契約

`seasonalOrbit({calendar, year, now})`の`calendar`は外部データとして検証する。

- `version`は候入り日データの版。年次日付を訂正する場合は、候名のマスター版とは別に更新する。成功時の`calendarVersion`に保持する。
- `timeZone`は候入り日を定義する明示的な時間帯。このアダプターは`Asia/Tokyo`と`UTC`のみ対応する。`Asia/Tokyo`はサマータイム終了後の1952年以降のデータに限る。他の時間帯とそれ以前の東京の暦は`unavailable`。画面はIssue #2/#11で採用した暦の時間帯を渡す。端末や日記設定の時間帯で置き換えない。日付だけの候入りデータを別時間帯へ変換しない。
- `master.version`は採用マスターの版。`risshunId`は最初の候のID。
- `master.kou`は72件。`id`は一意、`order`は1〜72。`sekkiId`で24節気を識別し、連続する3候の`position`を1〜3とする。
- `years`の各行は`year`、`masterVersion`、72件の`entries`、`nextRisshunDate`を持つ。`entries`は`kouId`と実際の候入り日`date`（YYYY-MM-DD）の組。
- `year`は立春が属する西暦。最初の候入り日は当年2月、`nextRisshunDate`は翌年2月。実日付の正しさと出典は暦提供側の責任で、計算で天文日付を推定しない。

配列順は問わない。マスター順に並べ、各IDの実日付を結び付ける。72件、節気内順序、一意性、日付の有効性、厳密な増加、版の一致を検証する。翌年のデータもある場合は、終了境界が翌年の立春と一致する必要がある。翌年全体がなくても明示された終了境界で選択年を計算できる。

## 出力と利用

成功は`kind: 'ready'`と72枠を返す。各枠は開始を含み終了を含まない。`upcoming`は未完成、`current`と`visited`は完成。haikuや記録件数を入力に含めないため、詠んだかどうかで進行は変わらない。過去年はすべて訪問済み、未来年はすべて未到来になる。

失敗は`kind: 'unavailable'`と理由を返し、枠を返さない。日付・版・年が欠けても5日刻みや前年の暦で補わない。画面側は暦未利用の状態を表示する。

`seasonalYear({calendar, now})`は供給済みの年境界から現在の季節年を求める。立春前は前年を選ぶ。該当する暦がない、または複数年が重なる場合は`null`。端末の西暦年だけで補完しない。保存済みの記録日は変更しない。

`shared/seasonal-orbit-browser.ts`の`watchSeasonalOrbit`は、指定年の結果を開始時と`pageshow`・`focus`・`visibilitychange`時に発行する。対応時間帯では現地日付が逆行しないため、次の候入り日の開始時刻を二分探索で求め、タイマーでも再評価する。長い待機はブラウザーのタイマー上限で区切る。バックグラウンドで遅延したタイマーは復帰時に現在時刻で再評価する。返された関数でタイマーと購読を解除する。現在年を追従する画面は、復帰時に`seasonalYear`を再解決し、選択年が変われば購読を作り直す。

## 検証

`npm test`は実在の暦ではないと明記した合成fixtureを使う。72枠の順序、立春前後、候入りのミリ秒境界、閏日、年越し、端末時間帯からの独立性、異なる現在時刻、欠損・重複・不正版・矛盾した翌年境界、遠い未来、非対応時間帯と歴史的な東京の暦の拒否、ブラウザー復帰と購読解除を検証する。採用日付の出典照合は`tests/calendar.test.mjs`で別途検証する。


## Issue #13 表示契約

SVGの`viewBox="0 0 600 600"`を使い、中心(300,300)、半径220、左上−135°から時計回りに5°ずつ72候を置く。絶対配置DOMと比較し、描画・境界・デバッグを同一座標で扱えるSVGを選んだ。幅と高さが異なる画面ではアスペクト比を維持して全体を縮小する。画面外にはみ出す拡大は行わない。

`shared/orbit-layout.ts`のID別レジストリが`scale`、`offsetX/Y`、`artworkBounds`、`touchBounds`、`motionBounds`（最大可動範囲）、`staticZ`を所有する。状態・暦配列の順番から座標を作らない。背景、ガイド、staticZ順の候を描き、選択候だけ最後に置く。周辺の候を記録数で動かさない。

`artwork`は`{kind:'provisional'}`または`{kind:'static',upcomingSrc,completedSrc}`。後者の2画像は同じ`artworkBounds`、アンカーと縮尺で差し替える。画像は事前制作の透過静止画とし、最大可動範囲が他の候を完全に覆わないようレビューする。transitionとidleの再生はこのIssueの実装には含まない。現状は静止画相当のSVG幾何形で、起動時の生成AI呼び出しはない。

「重なりレビュー」はアート・タッチ・最大可動範囲を描く。完全遮蔽の検査は、各アート矩形の13×13サンプル点が後続レイヤーの矩形の和集合に覆われるかを調べる保守的なレビュー補助であり、画像の透明部分を判定するものではない。アセット変更時は実画像でも確認する。

小さな画面では円環のタッチ領域が44pxを下回るため、常時表示する48px以上のネイティブ候選択欄を操作の代替とする。候名・読み・節気・状態を読み上げ、選択したIDと実期間を表示する。キーボードはネイティブ選択欄に加え、円環の最初または選択中の候でEnter・Spaceによる選択に対応する。アプリのホーム以外では非表示にし、アプリ言語がEnglishなら説明・操作ラベルを英語にする。採用された日本語の候名・読みは保持する。

「現在の季節年」は候入りタイマーとブラウザー復帰で立春を越えると翌季節年へ追従する。明示的に選んだ年は固定する。対応年外や欠損データは暦利用不可を表示し、代用の日付は生成しない。

`tests/orbit-layout.test.mjs`は採用データで0/12/42/72候のID、固定順序、最大範囲、和集合遮蔽検出を検証する。`tests/orbit-screen.test.mjs`は実アプリに記録・設定のAPI fixtureを使い、4段階のアンカーJSONとPNGを保存する。アンカー・変換・重なり順は完全一致させる。色・透明度を統一し、現在マーカー・文字を除いた幾何形PNGを画素比較する。アンチエイリアスの微小差を許容し、RGBAの成分差が10を超える画素を全体の0.1%以下に制限する。320/390/412/768/1280px、200%文字拡大、一覧と円環選択、キーボード、日英表示、ホーム限定、立春タイマーと固定年、欠損年を検証する。CIの画面検証に含める。実機iOS/AndroidやWebKitの確認はChromium上の幅検証では代替できない。
