# Sakkuの季節暦 v1

2026年10月12日。Issue #2・#11の実装仕様。Seasonal Orbitの画面接続はIssue #12で扱う。

## 採用する暦と境界

日本の本朝七十二候を採用する。候名・読みは「こよみのページ」のCSVを原文どおり保持する。同サイトの説明では明治時代の伊勢神宮略本暦に準拠し、意味を優先した文字遣いの変更を含む。別版の候名を混ぜたり、読みを自動修正したりしない。

候入り日は、同サイトが定気法で太陽中心の視黄経の5度刻みの通過を求めた日本時の日付を使う。二十四節気は15度刻みであり、各節気の初候に一致する。日付を固定月日や5日加算で生成しない。二十四節気の定義と日付の照合には国立天文台の資料を使う。

- 暦の基準時間帯は`Asia/Tokyo`。アプリの候・節気の境界は、提供された候入り日の午前0時。
- 天文学的な通過時刻そのものをアプリの切替時刻にしない。日付のみのCSVから天文時刻を復元しない。
- 候・節気の期間は開始日以上、次の開始日未満。
- 通番1〜72は立春から始まる固定順。候IDは`kou-01`〜`kou-72`、節気IDは立春を先頭に`sekki-01`〜`sekki-24`。
- 記録一覧の「一年」は西暦の1月1日から翌年1月1日未満。Seasonal Orbitの「季節年」は当年の実際の立春日から翌年の実際の立春日未満。両者を同じ年境界として扱わない。

## 記録日と旅行

記録日は`YYYY-MM-DD`という本人が指定した日付であり、UTCの瞬間ではない。既存の日付入力を使い、過去の日付も指定できる。季節暦の対応範囲外でも日付として有効なら記録を保持し、季節分類だけを利用不可とする。

日記の新規日付の初期値は日本時間の今日とする。端末の時間帯や海外滞在で候入り日と過去の記録日を変えない。初期版では日記時間帯の変更設定を設けない。将来変更可能にする場合も、既存の記録日を再計算せず、新規記録の初期値だけに適用する。

分類関数は保存済みの日付文字列をそのまま使う。記録の作成日時や端末時間帯から日付を推測しない。Seasonal Orbitの現在状態を求めるときだけ、現在の瞬間を日本時間の日付へ変換する。

## 収録範囲と欠損

初期の公開対応範囲は暦年2024〜2027と季節年2024〜2027。2023年分は1月の記録の季節年を実際の前年立春から判定するために保持する。2023〜2028指定のCSVを保持し、先頭より前の候入り日と末尾より後の境界を確保する。ファイル名の年を実際の収録範囲とみなさない。原本の余分な前後データは境界検証に利用し、それだけで公開対応年を広げない。

提供された2026年CSVは78行、72通番を含み、2025年12月22日〜2027年1月15日を収録する。今回再出力した2026年CSVと提供原本はバイト単位で一致した。2026年1月1日は2025年12月31日開始の66候に分類する。

範囲外、必要境界の欠落、未知の版、不正な原本は理由付きの利用不可とする。別年の月日、固定5日計算、空の候名で補わない。取り込み失敗時には現在版を置き換えない。

## 版と訂正

マスターと候入り日データを分離する。マスター版は候名・読み・節気・候内位置の内容に、暦データ版は正規化された内容と対応範囲に結び付ける。原本SHA256、取得情報、正規化処理版も残す。

公開した版付きJSONを上書き・削除しない。訂正は新しい版を追加し、現在版への参照を変更する。既存版を指定した分類は同じ結果を返す。名前や読みの変更も差分レビューの対象とする。

記録日は暦訂正の影響を受けない。現在版による閲覧分類は新しい版で変わり得るため、分類結果をキャッシュ・エクスポート・保存するときは暦データ版とマスター版を一緒に保存する。旧版での読み返しではその保存版を明示的に選ぶ。今回の整備はDBへの分類結果の自動書き込みや既存記録の一括再分類を行わない。

## 取得と利用条件

出典は[こよみのページ・本朝七十二候](https://koyomi8.com/sub/72kou.html)。2026年10月12日に[サイトポリシー](https://koyomi8.com/policy.html)を確認した。転載・引用を禁止する記述ではなく、出所の明示を求める内容である。このリポジトリは出典を保持し、独自に計算したデータと表示しない。

別の[暦データ配布ページ](https://koyomi8.com/databox.html)には使用・転載時のメール連絡に関する記述がある。同ページの配布データと72候計算ページのCSVは別の取得経路であり、その注意書きを無視した包括的な再配布許諾とは解釈しない。提供者への連絡は今回送信していない。公開製品への同梱時には適用範囲と連絡要否を確認する。

初期版はブラウザーのCSV出力を人が操作して取得する。指定年を選び「計算実行」を押し、結果の年を確認してCSVを保存する。アプリ表示時の外部取得や継続的なスクレイピングは行わない。

2026年原本の元の取得時刻は不明なため、`retrievedAt`を`null`とし、今回の受領確認時刻を別に記録する。他年は今回の取得確認時刻、指定年、実際の範囲、原本ハッシュを記録する。ファイルの更新日時を取得日時の証拠にしない。

国立天文台の[二十四節気の定義](https://eco.mtk.nao.ac.jp/koyomi/faq/24sekki.html)と[サイト利用規定](https://eco.mtk.nao.ac.jp/koyomi/site/)も確認した。同規定は届出不要での利用と、引用表記やリンクの設定を案内している。

## 更新運用

10月の年次チェックで現在年・翌年の暦年と季節年の不足を検知する。必要なCSVを手動で取得し、原本と取得情報を追加してから正規化を実行する。CSV形式・名称・読み・重複・巡回順・範囲の検証を通った差分だけをPRにする。

同じ原本の再実行は変更を作らない。失敗時は現在版を維持し、重複しない不足通知へまとめる。取得先の変更や自動取得の導入は、利用条件と取得手段を再確認してから行う。
